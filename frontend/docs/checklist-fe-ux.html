UX/UI — 5 requirements   Pass 5 / Partial 0 / Defer 0 / Fail 0

การออกแบบที่ใช้งานง่าย รองรับทุกขนาดหน้าจอ และสม่ำเสมอทั้ง application

1. Intuitive Design
หน้าเว็บเรียบง่าย ขั้นตอนชัดเจน มี breadcrumb และ navigation ที่สม่ำเสมอ
P2Pass

คืออะไร

Intuitive design คือหน้า UI ที่ user สามารถทำงานได้โดยไม่ต้องอ่านคู่มือ — layout ชัดเจน, สิ่งที่ clickable มีรูปแบบที่รู้จัก, breadcrumb บอกว่าอยู่ที่ไหน, navigation สม่ำเสมอทุกหน้า

ทำไมถึงสำคัญ

Financial dashboard ที่ซับซ้อน ถ้า user งง ก็ไม่กล้าใช้ หรือทำผิดพลาด breadcrumb ลด cognitive load ลง user รู้ว่าอยู่ที่ไหนใน flow และกลับไปหน้าก่อนหน้าได้ง่าย

สถานะในโปรเจกต์ ✓

  • Sidebar navigation คงที่ทุกหน้า — active state บอก current location
  • Breadcrumb component ใน src/components/atoms/Breadcrumb.vue ใช้ Vue Router meta
  • Layout template เดียวกันทุก page — header, sidebar, main content area
  • Action buttons ใช้ variant สม่ำเสมอ (primary / secondary / danger)

วิธีทดสอบ

เปิด browser แล้วนำทางผ่าน 3 ระดับ hierarchy — breadcrumb ต้องแสดง path ครบและ clickable ทุก segment กลับไปหน้าก่อนหน้าได้

2. Responsive Design
แสดงผลสมบูรณ์บนทุกหน้าจอ ตั้งแต่ mobile 375px ถึง 4K display
P2Pass

คืออะไร

Responsive design คือ layout ที่ปรับตัวตามขนาดหน้าจออัตโนมัติ โดยไม่ต้องทำ website แยกสำหรับ mobile กับ desktop ใช้ CSS breakpoints กำหนดว่าแต่ละ viewport จะแสดงผลอย่างไร

ทำไมถึงสำคัญ

Finance admin อาจ check ตัวเลขบนมือถือระหว่างประชุม หรือดู dashboard บนจอ 4K ในห้องบอร์ด layout ที่ไม่ responsive ทำให้ข้อมูลถูก clip หรืออ่านไม่ได้ ส่งผลต่อ trust ในตัวเลข

สถานะในโปรเจกต์ ✓

  • Tailwind CSS breakpoints: sm:375px · md:768px · lg:1024px · xl:1280px · 2xl:1536px
  • Grid layout ใช้ grid-cols-1 md:grid-cols-2 xl:grid-cols-3 pattern
  • Sidebar collapse เป็น drawer บน mobile (<768px)
  • ตารางข้อมูลใช้ horizontal scroll บน viewport แคบ

วิธีทดสอบ

ใช้ Chrome DevTools → Toggle device toolbar ทดสอบที่ 375px (iPhone SE), 768px (tablet), 1280px (laptop), 1920px (desktop)

# ทดสอบอัตโนมัติด้วย Playwright
npx playwright test tests/e2e/responsive.spec.ts
3. Design System (Token-based)
กำหนด color token, typography scale, spacing scale, component library ใช้สม่ำเสมอทั้งเว็บ
P2Pass

คืออะไร

Design system คือชุด tokens และ components ที่กำหนดรูปแบบ visual ของ application สี, ขนาดตัวอักษร, ระยะห่าง ถูกกำหนดเป็น variables ส่วนกลาง component ทุกตัวใช้ tokens เดียวกัน ทำให้ visual สม่ำเสมอ

ทำไมถึงสำคัญ

ถ้าไม่มี design system นักพัฒนาแต่ละคนจะใช้สีและขนาดต่างกัน ผลคือ UI ดูไม่ consistent และ user รู้สึกว่าระบบไม่ professional ซึ่งกระทบ trust ในตัวเลขที่แสดง

สถานะในโปรเจกต์ ✓

  • tailwind.config.ts: กำหนด color palette, font family, spacing scale เป็น custom tokens
  • src/components/atoms/: Button, Badge, Input, Card — ใช้ tokens ผ่าน Tailwind classes
  • src/components/molecules/: DataTable, FilterBar, StatCard
  • Typography: heading scale กำหนดใน Tailwind fontSize config

4. Dark Mode Support
รองรับ prefers-color-scheme สลับ light/dark ได้ ตัวเลขและกราฟต้องอ่านง่ายในทั้งสอง mode
P4Pass

คืออะไร

Dark mode คือ UI variant ที่ใช้พื้นหลังเข้มและข้อความสว่าง ลดแสงสีฟ้าและความเมื่อยล้าสายตาในสภาพแวดล้อมที่มีแสงน้อย ระบบรองรับได้ 2 วิธี: ตาม OS preference อัตโนมัติ (prefers-color-scheme) หรือมี toggle ให้ user เลือกเอง

ทำไมถึงสำคัญ

User ที่ทำงานกลางคืนหรือในห้องที่แสงน้อย dark mode ช่วยได้มาก นอกจากนี้ graph และ chart ต้องยังอ่านได้ — contrast ของสีข้อมูลต้องผ่าน WCAG ทั้งใน light และ dark mode

สถานะในโปรเจกต์ ✓

  • CSS variable theming ใน src/style.css — dark default ที่ :root, light override ที่ :root[data-theme="light"]
  • Composable src/composables/useTheme.ts — toggle data-theme บน <html> และ persist ใน localStorage
  • Theme toggle button ใน sidebar ของ AppLayout.vue — แสดง icon sun/moon ตาม theme ปัจจุบัน
  • Charts (TrendChart ฯลฯ) ใช้ useTheme() และ recompute palette เมื่อ theme เปลี่ยน
  • Default theme: dark — ค่าที่ persist ใน localStorage จะถูกนำมาใช้ทันทีก่อน Vue mount
// src/composables/useTheme.ts
const theme = ref<Theme>((localStorage.getItem('theme') as Theme) || 'dark')
watchEffect(() => {
  document.documentElement.setAttribute('data-theme', theme.value)
  localStorage.setItem('theme', theme.value)
})
export function useTheme() {
  const toggle = () => { theme.value = theme.value === 'dark' ? 'light' : 'dark' }
  const isDark = () => theme.value === 'dark'
  return { theme, toggle, isDark }
}

วิธีทดสอบ

  1. เปิด app → คลิกปุ่ม Light mode / Dark mode ใน sidebar ล่าง — หน้าจอต้องสลับ theme ทันที
  2. Refresh browser — theme ต้องคงเดิม (ตรวจสอบ localStorage.getItem('theme') ใน DevTools Console)
  3. ตรวจสอบ chart ใน light mode ว่า axis label, grid, tooltip อ่านได้ชัดเจน (ไม่มีสีขาวบนพื้นขาว)
  4. ใช้ axe DevTools extension ตรวจ color contrast ratio ทั้ง light และ dark — ต้องผ่าน WCAG AA (≥4.5:1 สำหรับ text)
5. Empty State Design
ออกแบบ empty state ทุก view: เมื่อไม่มีข้อมูล, ไม่มีสิทธิ์, หรือ filter ไม่เจอผล
P3Pass

คืออะไร

Empty state คือสิ่งที่แสดงเมื่อ content area ไม่มีข้อมูล มี 3 กรณีหลัก: (1) ข้อมูลยังไม่มี (first use), (2) filter ไม่เจอผล, (3) ไม่มีสิทธิ์ดูข้อมูลนั้น แต่ละกรณีควร communicate แตกต่างกัน พร้อม action ที่เหมาะสม

ทำไมถึงสำคัญ

ถ้าแสดงพื้นที่ว่างเปล่าโดยไม่มีคำอธิบาย user จะไม่รู้ว่าระบบพัง, filter ผิด, หรือไม่มีสิทธิ์ ความสับสนนี้ทำให้ user ไม่เชื่อถือตัวเลขและระบบ

สถานะในโปรเจกต์ ✓

  • สร้าง src/components/atoms/EmptyState.vue — รองรับ 3 variant: no-data, no-results, no-permission
  • แต่ละ variant มี icon, title, description เป็นค่า default ภาษาไทย และ override ผ่าน props ได้
  • <slot name="action"> สำหรับปุ่ม action เช่น "ล้าง filter" หรือ link ติดต่อ admin
  • ใช้ใน DataTable.vue (prop emptyVariant), PivotTable.vue, IoPivotTable.vue
  • BudgetView.vue: แสดง no-results + ปุ่ม "ล้าง filter" เมื่อ kpis.doc_count === 0
  • IoView.vue: แสดง no-results + ปุ่ม "ล้าง filter" เมื่อ kpis.total_amount === 0
// EmptyState.vue — 3 built-in variants
<EmptyState variant="no-data" />
<!-- ยังไม่มีข้อมูลในระบบสำหรับช่วงเวลานี้ -->

<EmptyState variant="no-results">
  <template #action>
    <button @click="filter.$reset()">ล้าง filter</button>
  </template>
</EmptyState>

<EmptyState variant="no-permission" />
<!-- คุณไม่มีสิทธิ์ดูข้อมูลนี้ กรุณาติดต่อผู้ดูแลระบบ -->

วิธีทดสอบ

  1. No results: ตั้ง filter เดือนที่ไม่มีข้อมูล (เช่น เดือนอนาคต) → BudgetView และ IoView ต้องแสดง EmptyState พร้อมปุ่ม "ล้าง filter" — คลิกแล้ว filter ต้องถูกรีเซ็ต
  2. DataTable empty: ส่ง :rows="[]" ให้ DataTable → ต้องแสดง EmptyState แทนแถวว่าง
  3. PivotTable empty: filter ที่ไม่มี GL detail → PivotTable และ IoPivotTable ต้องแสดง EmptyState
  4. Accessibility: ใช้ axe DevTools ตรวจว่า EmptyState ไม่มี contrast issue ทั้ง light และ dark mode
