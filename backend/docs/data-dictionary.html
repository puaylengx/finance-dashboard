Data Dictionary — Seamless Dashboard Database

PostgreSQL database schema พร้อม business meaning สำหรับทุก column

main transaction data   master reference / lookup   system app management   audit immutable trail

main

erp_transactions

ข้อมูล transaction ทางการเงินที่ sync มาจากระบบ ERP (SAP) ขององค์กร แต่ละ row คือ 1 รายการค่าใช้จ่ายที่ผ่านการอนุมัติแล้ว ข้อมูลเข้าระบบผ่าน ETL batch (import_erp.py) ไม่ใช่ real-time feed
Migration: 001_create_finance_tables.sql + 005_rename_erp_table.sql

ColumnTypeRequiredความหมายทางธุรกิจ
fiscal_year idxBIGINTNOT NULLปีงบประมาณ (Thai fiscal year: ต.ค.–ก.ย.) เช่น 2568 = FY2025 เป็น filter หลักของทุก dashboard query
fiscal_month idxBIGINTNOT NULLเดือนงบประมาณ 1–16 (SAP ERP รองรับ 16 periods — period 13-16 คือ closing periods)
trimesterBIGINTNOT NULLไตรมาสงบประมาณ 1–4 ใช้สำหรับ group ใน report ไตรมาส
dayBIGINTNOT NULLวันที่ของเดือน (1–31) ดึงจาก doc_date

gl_id idxTEXTNOT NULLGeneral Ledger Account ID — รหัสบัญชีแยกประเภท เช่น 5100xxxx = ค่าวัสดุ, 5200xxxx = ค่าจ้าง FK ไปยัง master_gl.gl_id
gl_descriptionTEXTNOT NULLชื่อบัญชี GL ดึงมาจาก SAP ตอน ETL import (denormalized เพื่อ query speed)

detailsTEXTNOT NULLรายละเอียดรายการ — free text จาก SAP posting note

system

finance_coordinator

รายชื่อ Finance Coordinator ที่ได้รับสิทธิ์พิเศษในการดู dashboard ทุก cost center ผู้ใช้ที่ถูก toggle active=TRUE จะได้รับ coordinator role ใน JWT token ผ่าน cache
Migration: 003_create_coordinator.sql

ColumnTypeRequiredความหมาย
id PKSERIALNOT NULLAuto-increment primary key
username idx uniqueTEXTNOT NULL UNIQUEUsername ของ coordinator — ตรงกับ sub field ใน JWT token (Entra ID UPN)
active partial idxBOOLEANNOT NULL DEFAULT TRUEสถานะ — TRUE = มีสิทธิ์ coordinator, FALSE = ถูก revoke ชั่วคราว; Partial index ที่ active=TRUE เพิ่ม performance การ lookup
created_atTIMESTAMPTZNOT NULLวันเวลาที่เพิ่ม coordinator
updated_atTIMESTAMPTZNULLวันเวลาที่ toggle ล่าสุด — ใช้สำหรับ optimistic locking (X-Expected-Updated-At header)
created_by / updated_byTEXTNULLusername ของ FA ที่ทำการ add/toggle coordinator
Locking: toggle_coordinator ใช้ pessimistic lock (SELECT FOR UPDATE) + optimistic lock (expected_updated_at header) → 409 conflict ถ้า concurrent modification  ·  Cache: Redis key seamless:v1:auth:coordinator:{username} ถูก invalidate ทุกครั้งที่ toggle

audit_log

บันทึกทุก authenticated API request ที่เกี่ยวกับข้อมูลการเงิน ออกแบบเป็น append-only — ควร REVOKE UPDATE, DELETE permission จาก app user ใน production
Migration: 006_create_audit_log.sql

ColumnTypeRequiredความหมาย
id PKBIGSERIALNOT NULLAuto-increment primary key (BIGSERIAL รองรับ row จำนวนมาก)
user_id idxTEXTNOT NULLJWT subject (sub) — email หรือ UPN ของผู้ใช้ที่ทำ request
actionTEXTNOT NULLสิ่งที่ทำ เช่น GET /api/v1/finance/dashboard, POST /api/v1/coordinator
resourceTEXTNULLResource identifier — เช่น coordinator ID ที่ถูก toggle
ip_addressINETNULLIP address ของ client (IPv4 หรือ IPv6)
status_codeSMALLINTNULLHTTP response code — 200/403/409/500 ช่วย filter requests ที่ fail
timestamp idx DESCTIMESTAMPTZNOT NULL DEFAULT now()วันเวลาที่ทำ request (timezone-aware) Index แบบ DESC เพราะ query มักดูข้อมูลล่าสุดก่อน
Append-only design: Production ควรรัน REVOKE UPDATE, DELETE ON audit_log FROM <app_user>; เพื่อป้องกัน tampering  ·  Query audit trail: SELECT * FROM audit_log WHERE user_id = $1 ORDER BY timestamp DESC LIMIT 50;
