Security — 11 requirements   Pass 6 / Partial 2 / Fail 3

ความปลอดภัยของ API, authentication, authorization, และการป้องกัน attack vectors ต่างๆ

1. JWT Authentication
ใช้ JWT token มาตรฐาน พร้อมกำหนด expiry
P1Pass

คืออะไร

JWT (JSON Web Token) คือ token ที่มี payload เข้ารหัสไว้ภายใน ประกอบด้วย header (algorithm), payload (claims เช่น user id, role), และ signature ที่ verify ได้โดยไม่ต้อง query database ทุกครั้ง

ทำไมถึงสำคัญ

Stateless auth ทำให้ server ไม่ต้องเก็บ session ทำให้ scale ง่าย token มี expiry ทำให้ถ้าถูก compromise ก็ใช้ได้แค่ชั่วคราว claims ใน payload ทำให้รู้ role/permission โดยไม่ต้อง query DB ทุก request

สถานะในโปรเจกต์ ✓

HS256 algorithm · expiry ตั้งได้ผ่าน JWT_EXPIRES_SECONDS (default 3600s) payload: {sub, role, position, coordinator, iat, exp} · core/security.py

{"sub": "user@example.com", "role": "fa", "position": "chief",
 "coordinator": false, "iat": 1717300000, "exp": 1717303600}
2. Microsoft Entra ID (SSO)
Auth ผ่าน Microsoft Entra ID รับ job_title เพื่อกำหนดสิทธิ์
P1Pass

คืออะไร

Microsoft Entra ID (เดิมชื่อ Azure AD) คือ enterprise identity provider ที่องค์กรส่วนใหญ่ใช้ SSO (Single Sign-On) ทำให้ user login ครั้งเดียวใช้ได้ทุก app ไม่ต้องจำ password แยกสำหรับแต่ละระบบ

ทำไมถึงสำคัญ

User ไม่ต้องสร้าง account ใหม่ — ใช้ account องค์กรที่มีอยู่แล้ว IT ยังคุม access ได้ส่วนกลาง (ถ้าไล่พนักงานออก revoke access ครั้งเดียวหมดทุก app) ลดความเสี่ยงจาก weak password

สถานะในโปรเจกต์ ✓

auth_service.py:94-177 — validate MS Entra token ด้วย JWKS (RS256) extract jobTitle → parse เป็น role/position issue JWT ของระบบ

draft_login สำหรับ dev โดยไม่ต้องเชื่อม Azure จริง (เมื่อ DRAFT_MODE=true)

3. Coordinator Authorization
ตรวจสอบ username ในตาราง finance_coordinator เพิ่มเติม
P1Pass

คืออะไร

นอกจาก position-based access (chairman/chief/head) ยังมี whitelist table finance_coordinator ที่ admin เพิ่มชื่อ user เข้าได้ด้วยตนเอง user ที่อยู่ใน table นี้ (และ active=true) เข้าระบบได้แม้ไม่มี position

ทำไมถึงสำคัญ

ทำให้ยืดหยุ่น — บางคนอาจไม่มี position ใน Entra แต่ต้องการสิทธิ์เข้าระบบ (เช่น เจ้าหน้าที่ประสานงาน) admin จัดการได้โดยไม่ต้องเปลี่ยน Entra attributes

สถานะในโปรเจกต์ ✓

auth_service.py:35-66 ตรวจ Redis cache ก่อน (key: seamless:coordinator:{username} TTL 600s) ถ้า miss ค่อย query finance_coordinator table toggle active/inactive ผ่าน PATCH /admin/coordinators/{id} · invalidate cache อัตโนมัติ

4. HTTPS / TLS
บังคับ HTTPS ทุก endpoint, redirect HTTP → HTTPS, ใช้ TLS 1.2+ เท่านั้น
P1Partial

คืออะไร

HTTPS เข้ารหัส traffic ระหว่าง browser และ server ด้วย TLS ป้องกัน man-in-the-middle attack ที่ดักอ่าน JWT token หรือ financial data ที่ส่งผ่านเครือข่าย TLS 1.2+ คือ version ที่ปลอดภัย (1.0 และ 1.1 ถูก deprecated แล้ว)

ทำไมถึงสำคัญ

ถ้าใช้ HTTP ธรรมดา JWT token จะถูก intercept ได้ง่ายในเครือข่ายสาธารณะ สำหรับ financial dashboard ที่มีข้อมูลงบประมาณ การเข้ารหัส in-transit เป็น baseline security requirement

สถานะในโปรเจกต์

App-level: Strict-Transport-Security header ตั้งค่าเมื่อ DEBUG=false (main.py:87) ✓ — บอก browser ว่าให้ใช้ HTTPS เท่านั้น

Infra-level: HTTP→HTTPS redirect และ TLS certificate management ต้องทำที่ reverse proxy (Nginx, Caddy, Traefik) ซึ่งยังไม่มี config

สิ่งที่ต้องทำ

  • ตั้งค่า reverse proxy (Nginx/Caddy) ให้รับ port 443 พร้อม TLS certificate (Let's Encrypt)
  • Redirect HTTP (port 80) → HTTPS (port 443) อัตโนมัติ
  • ตั้งค่า ssl_protocols TLSv1.2 TLSv1.3 ใน Nginx config
  • ตรวจสอบ DEBUG=false ใน production เพื่อให้ HSTS header ทำงาน
5. SQL Injection Prevention
ใช้ parameterized query เสมอ ห้าม string concatenation ใน SQL
P1Pass

คืออะไร

SQL Injection คือ attack ที่ใส่ SQL code ใน user input เช่น year=2025; DROP TABLE erp_transactions-- ถ้า code ทำ string concat จะกลายเป็น SQL ที่ทำลายข้อมูล Parameterized query แก้ปัญหานี้ด้วยการส่ง user input เป็น parameter แยกจาก SQL statement

ทำไมถึงสำคัญ

SQL Injection เป็น OWASP Top 10 อันดับ 1 มาหลายปี ถ้าถูก exploit ผู้โจมตีสามารถอ่าน แก้ไข หรือลบข้อมูลทั้ง database ได้ สำหรับ financial data ความเสียหายร้ายแรงมาก

สถานะในโปรเจกต์ ✓

ทุก SQL query ใช้ %(name)s parameterized syntax ผ่าน psycopg3 AsyncClientCursor

await cur.execute(
    "SELECT 1 FROM finance_coordinator WHERE username = %(username)s",
    {"username": username}  # user input เป็น param แยก
)

ไม่มี f-string หรือ string concat ใน SQL ทั้ง codebase

6. Rate Limiting
จำกัด request ต่อ IP ต่อหน่วยเวลา ด้วย slowapi
P1Pass

คืออะไร

Rate limiting คือการจำกัดจำนวน request ที่แต่ละ IP หรือ user ส่งได้ใน time window เช่น 100 request/minute เมื่อเกิน limit จะตอบ 429 Too Many Requests

ทำไมถึงสำคัญ

ป้องกัน 3 สถานการณ์: (1) DDoS attack ที่ส่ง request จำนวนมากเพื่อทำให้ server ล่ม (2) brute force attack ที่ลอง password หลายครั้ง (3) scraping ที่ดึงข้อมูลเกินควร

สถานะในโปรเจกต์ ✓

Global: 100 req/min per IP (main.py:45) · Auth endpoints: 10 req/min per IP (auth.py:27)

ใช้ slowapi + SlowAPIMiddleware · ตอบ 429 พร้อม Retry-After header อัตโนมัติ

7. Secret Management
เก็บ credential / API key ใน Vault หรือ secret manager ห้ามเก็บใน .env ที่ commit เข้า repo
P1Partial

คืออะไร

Secret management คือกระบวนการเก็บ credential (password, API key, JWT secret) อย่างปลอดภัย เพื่อไม่ให้ secret หลุดผ่าน version control, log, หรือ environment ที่ไม่ควรเห็น tools ที่ใช้ได้แก่ HashiCorp Vault, AWS Secrets Manager, Azure Key Vault

ทำไมถึงสำคัญ

Secret ที่ commit เข้า git จะอยู่ใน history ตลอดไปแม้จะ delete ภายหลัง มี bots ที่ scan GitHub อัตโนมัติหา API key และนำไปใช้ภายในนาที default value ที่ลืมเปลี่ยนเป็น vulnerability ที่พบบ่อยมาก

สถานะในโปรเจกต์

ใช้ .env file ที่อยู่ใน .gitignore ✓ — ไม่ commit secret เข้า repo

.env.example มี placeholder แทน value จริง ✓

แต่: default JWT_SECRET_KEY=change-me-in-production ใน config.py:52 — ถ้าลืมตั้งใน production จะเป็น vulnerability ร้ายแรง

ยังไม่ใช้ Vault หรือ cloud secret manager — เป็น plain text ใน file system

สิ่งที่ต้องทำ

  • เพิ่ม startup validation: ถ้า JWT_SECRET_KEY == "change-me-in-production" และ DEBUG=false → crash ทันที
  • Production: ย้ายไปใช้ Azure Key Vault (เข้ากันกับ Entra ID) หรือ AWS Secrets Manager
  • Rotate JWT secret ทุก 90 วัน กำหนด schedule และ process
  • ตรวจสอบว่า .env ไม่ถูก backup ไปยัง cloud storage โดยไม่ตั้งใจ
8. Token Refresh & Revocation
รองรับ silent refresh, revoke token เมื่อ logout หรือเมื่อตรวจพบพฤติกรรมผิดปกติ
P2Fail

คืออะไร

Refresh token คือ long-lived token ที่ใช้ขอ access token ใหม่โดยที่ user ไม่ต้อง login ซ้ำ Token revocation คือความสามารถในการยกเลิก token ที่ยังไม่หมดอายุ เช่น หลัง logout หรือเมื่อ token ถูก compromise

ทำไมถึงสำคัญ

JWT เป็น stateless — ถ้าถูกขโมย server ไม่มีทางรู้ว่าควร reject ได้จนกว่า expiry ในกรณี financial system ถ้า user แจ้งว่า token ถูกขโมย ควรยกเลิกได้ทันที ไม่ต้องรอ 1 ชั่วโมง

สถานะในโปรเจกต์ — ยังไม่มี

ไม่มี POST /auth/refresh endpoint · ไม่มี refresh token · ไม่มี logout/revoke endpoint · token หมดอายุ = user ต้อง login ใหม่เท่านั้น

สิ่งที่ต้องทำ

  • เพิ่ม POST /auth/logout: blacklist JWT jti (unique id) ใน Redis จนถึง expiry
  • เพิ่ม POST /auth/refresh: รับ long-lived refresh token (30 วัน) → issue access token ใหม่ (1 ชั่วโมง)
  • แก้ deps.py ให้ check Redis blacklist ก่อน allow request
  • ใน security headers เพิ่ม Clear-Site-Data เมื่อ logout
9. Audit Log (Immutable)
บันทึกทุก action บนข้อมูลการเงิน: ใคร ทำอะไร เมื่อไร IP อะไร แก้ไขย้อนหลังไม่ได้
P1Fail

คืออะไร

Audit log คือ immutable record ของทุก action ที่เกิดในระบบ ระบุ: user ที่ทำ, action ที่ทำ, timestamp, IP address, resource ที่ถูกกระทำ และ result "Immutable" หมายถึงแก้ไขหรือลบย้อนหลังไม่ได้ (append-only)

ทำไมถึงสำคัญ

สำหรับ financial system audit log เป็น requirement ด้าน compliance (การตรวจสอบบัญชี) และ forensics (สืบสวนเมื่อมีการ fraud หรือ data breach) ถ้าไม่มีจะไม่รู้ว่าใคร access ข้อมูลอะไร เมื่อไร ทำให้ตรวจสอบย้อนหลังไม่ได้

สถานะในโปรเจกต์ — ยังไม่มี

มีเพียง logs/app.log (rotating file) ที่ log login success/fail เท่านั้น ไม่มี: ใครดูข้อมูลไหน เมื่อไร · ไม่มี immutable storage · log ถูก rotate ทุก 10MB ทำให้ข้อมูลเก่าหายได้

สิ่งที่ต้องทำ (สำคัญมาก)

  • สร้าง audit_log table ใน DB: id, user_id, action, resource, ip_address, timestamp, result
  • เพิ่ม audit logging middleware ที่บันทึกทุก authenticated request ไปยัง table นี้
  • ให้ table เป็น append-only: ไม่มี UPDATE/DELETE — ใช้ DB-level permission
  • Log ข้อมูลขั้นต่ำ: GET /finance → บันทึก user, params ที่ใช้ filter, timestamp
  • Retain audit log อย่างน้อย 7 ปีตาม best practice financial compliance
10. PDPA / Data Privacy
ปฏิบัติตาม PDPA สำหรับข้อมูลส่วนบุคคล รวมถึง data minimization และ right to erasure
P2Fail

คืออะไร

PDPA (พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562) คือกฎหมายไทยที่กำหนดว่าต้องเก็บข้อมูลส่วนบุคคลเท่าที่จำเป็น (data minimization), ได้รับ consent, มีกระบวนการให้ผู้ใช้ขอลบข้อมูลได้ (right to erasure)

ทำไมถึงสำคัญ

องค์กรที่ฝ่าฝืน PDPA มีโทษปรับสูงสุด 5 ล้านบาทต่อกรรม ข้อมูลที่ระบบมีที่เป็น personal data ได้แก่ username (อาจเป็น email), display name, job_title จาก Entra

สถานะในโปรเจกต์ — ยังไม่มี

ไม่มี data minimization policy · ไม่มี consent mechanism · ไม่มี right to erasure · ไม่มี data retention policy · ไม่มี privacy notice

สิ่งที่ต้องทำ

  • ระบุว่าข้อมูลไหนใน system เป็น personal data และ data subject คือใคร
  • เพิ่ม DELETE /admin/users/{username}: anonymize/delete ข้อมูล personal data ตามคำขอ
  • กำหนด data retention: coordinator records เก็บนานแค่ไหน หลังจากนั้น anonymize
  • จัดทำ Privacy Notice และ Data Processing Agreement
  • ตรวจสอบกับ legal team ว่า data ใดบ้างที่เข้าข่าย PDPA
11. Security Headers
ตั้งค่า HTTP headers: CSP, X-Frame-Options, X-Content-Type-Options, HSTS
P1Pass

คืออะไร

Security headers คือ HTTP response headers ที่บอก browser ว่าต้องทำงานอย่างไรเพื่อความปลอดภัย เช่น X-Frame-Options: DENY ป้องกัน clickjacking, X-Content-Type-Options: nosniff ป้องกัน MIME sniffing, HSTS บังคับ HTTPS

ทำไมถึงสำคัญ

Headers เหล่านี้เป็น defense-in-depth ที่ป้องกัน attack class ต่างๆ: clickjacking (iframe embedding), XSS via MIME type confusion, downgrade attacks (HTTP แทน HTTPS) ส่วนใหญ่ตั้งครั้งเดียวได้ประโยชน์สูง

สถานะในโปรเจกต์ ✓

main.py:79-88 middleware ตั้งทุก response:

X-Content-Type-Options: nosniff
X-Frame-Options: DENY
X-XSS-Protection: 1; mode=block
Referrer-Policy: strict-origin-when-cross-origin
Strict-Transport-Security: max-age=31536000; includeSubDomains  # production only

ยังไม่มี Content-Security-Policy — ควรเพิ่มเพื่อป้องกัน XSS ที่ซับซ้อนขึ้น
