Accessibility — 2 requirements   Pass 2 / Partial 0 / Defer 0 / Fail 0

การรองรับผู้ใช้ทุกกลุ่ม ครอบคลุม WCAG 2.1 AA standard และ screen reader compatibility

1. WCAG 2.1 AA
ใช้ color contrast ratio ≥ 4.5:1, ARIA labels ครบ, keyboard navigation ทุก interactive element
P3Pass

คืออะไร

WCAG 2.1 AA (Web Content Accessibility Guidelines) คือมาตรฐานระดับ AA ที่กำหนดว่า web content ต้อง perceivable, operable, understandable, และ robust สำหรับผู้ใช้ทุกกลุ่ม รวมถึงผู้พิการทางสายตาและการเคลื่อนไหว

ทำไมถึงสำคัญ

ระบบ internal ของหน่วยงานรัฐหรือองค์กรขนาดใหญ่หลายแห่งกำหนดให้ต้องผ่าน WCAG AA นอกจากนี้ design ที่ accessible มักเป็น design ที่ดีและใช้งานง่ายสำหรับทุกคนด้วย

สถานะในโปรเจกต์ ✓

  • Color contrast: Tailwind color palette ที่เลือกผ่าน contrast ratio ≥ 4.5:1 — ตรวจยืนยันด้วย axe DevTools
  • ARIA labels: ทุก icon button มี aria-label, ทุก form input มี <label> หรือ aria-labelledby
  • Keyboard navigation: ทุก interactive element (button, link, select, modal) navigable ด้วย Tab และ Enter/Space
  • Focus indicator: visible focus ring บนทุก focused element — ไม่มี outline: none โดยไม่มี custom focus style แทน
  • Semantic HTML: ใช้ <button>, <nav>, <main>, <table> ถูกประเภท
<!-- ตัวอย่าง accessible table -->
<table role="table" aria-label="งบประมาณประจำปี 2568">
  <caption class="sr-only">ตารางงบประมาณแสดงยอดคงเหลือรายแผนก</caption>
  <thead>
    <tr>
      <th scope="col">แผนก</th>
      <th scope="col">งบประมาณ</th>
      <th scope="col">ใช้ไปแล้ว</th>
      <th scope="col">คงเหลือ</th>
    </tr>
  </thead>
</table>

วิธีทดสอบ

  • ติดตั้ง axe DevTools browser extension → Run full page scan → ต้องไม่มี violation ระดับ critical/serious
  • ทดสอบ keyboard-only navigation: ปิด mouse แล้วนำทางทั้งหน้าด้วย Tab เท่านั้น
  • ตรวจ contrast: เปิด Chrome DevTools → Rendering → Emulate vision deficiencies
# ทดสอบ WCAG อัตโนมัติใน Playwright
import { checkA11y } from 'axe-playwright'
test('dashboard passes WCAG 2.1 AA', async ({ page }) => {
  await page.goto('/dashboard')
  await checkA11y(page, null, {
    runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa'] }
  })
})
2. Screen Reader Support
ทดสอบกับ NVDA / VoiceOver ตาราง chart และ form ต้องอ่านได้ถูกต้อง
P3Pass

คืออะไร

Screen reader คือ assistive technology ที่อ่าน UI ออกเสียงสำหรับผู้พิการทางสายตา NVDA (Windows) และ VoiceOver (macOS/iOS) เป็น screen reader ที่พบบ่อยที่สุด การทดสอบกับเครื่องมือเหล่านี้ยืนยันว่า ARIA markup ทำงานได้จริง ไม่ใช่แค่ผ่าน automated scan

ทำไมถึงสำคัญ

Financial data ที่อ่านไม่ออกสำหรับผู้ใช้ screen reader หมายความว่าผู้พิการทางสายตาไม่สามารถทำหน้าที่ FA หรือ Coordinator ได้ เป็นทั้ง accessibility issue และ legal issue ในบางประเทศ

สถานะในโปรเจกต์ ✓

  • ตาราง: <th scope="col/row"> ถูกต้อง screen reader อ่าน header ก่อน cell value อัตโนมัติ
  • Chart: แต่ละ chart มี aria-label สรุปข้อมูล + role="img" และมี data table hidden (.sr-only) เป็น alternative
  • Form: ทุก input มี <label for> หรือ aria-label error message เชื่อมด้วย aria-describedby
  • Modal/Dialog: ใช้ role="dialog" + aria-modal="true" + focus trap ภายใน modal
  • Live region: notification toast ใช้ aria-live="polite" — screen reader อ่านเมื่อปรากฏ
<!-- Chart accessible pattern -->
<figure role="img" aria-labelledby="chart-title" aria-describedby="chart-desc">
  <figcaption id="chart-title">งบประมาณปี 2568 รายแผนก</figcaption>
  <p id="chart-desc" class="sr-only">
    กราฟแท่งแสดงงบประมาณ 8 แผนก สูงสุด: IT 12.5 ล้านบาท
    ต่ำสุด: Admin 2.1 ล้านบาท
  </p>
  <canvas ...></canvas>
</figure>

<!-- sr-only utility class -->
.sr-only {
  position: absolute; width: 1px; height: 1px;
  padding: 0; margin: -1px; overflow: hidden;
  clip: rect(0,0,0,0); white-space: nowrap; border: 0;
}

วิธีทดสอบ

macOS VoiceOver (ฟรี, built-in)

  • เปิด: Cmd + F5 หรือ System Settings → Accessibility → VoiceOver
  • นำทางด้วย Tab — VoiceOver ต้องอ่าน label ของ element ที่ focus อยู่
  • บนตาราง: ใช้ Control + Option + Arrow นำทาง — ต้องได้ยิน header และ cell value
  • บน chart: VoiceOver ต้องอ่าน aria-label ที่สรุปข้อมูล

ผลที่คาดหวัง: ทุก interactive element อ่านออกว่าคืออะไรและทำอะไรได้ ตัวเลขในตารางอ่านถูกต้องพร้อม header context

Accessibility — ครบทุกข้อ ✓

Accessibility เป็น หมวดที่ผ่านครบ 2/2 ข้อ ความท้าทายต่อไปคือรักษา standard นี้ไว้เมื่อเพิ่ม feature ใหม่ โดยเฉพาะ component ใหม่ที่จะเพิ่มใน roadmap เช่น virtual scroll table (ต้องการ ARIA grid pattern) และ dark mode (ต้องผ่าน contrast check ทั้ง 2 theme)
