1. Architecture Decision Records (ADR)
บันทึกการตัดสินใจด้าน architecture สำคัญ พร้อม context และ trade-off
P3Pass

คืออะไร

ADR คือ document สั้นๆ ที่บันทึกการตัดสินใจด้าน architecture แต่ละครั้ง ได้แก่: (1) Context — ทำไมถึงต้องตัดสินใจ (2) Decision — ตัดสินใจอะไร (3) Consequences — ผลที่ตามมา ทั้ง positive และ negative

สถานะในโปรเจกต์ ✓

มี ADR directory backend/docs/adr/ พร้อม 4 ADR files ครอบคลุม decision สำคัญ:

  • 001-ssh-tunnel-db-connection.md — ทำไมถึงใช้ SSH tunnel แทนการเปิด DB port
  • 002-psycopg3-async-over-sqlalchemy.md — ทำไมถึงใช้ psycopg3 โดยตรงแทน SQLAlchemy ORM
  • 003-draft-mode-local-auth.md — ทำไมถึงมี Draft Mode สำหรับ local development
  • 004-redis-response-caching.md — ทำไมถึงเลือก Redis เป็น response cache

วิธีทดสอบ / ตรวจสอบ

# ตรวจว่า ADR files มีครบ
ls backend/docs/adr/
# คาดหวัง: 001-ssh-tunnel-db-connection.md, 002-psycopg3-async-over-sqlalchemy.md
#           003-draft-mode-local-auth.md, 004-redis-response-caching.md

# เปิดอ่าน ADR หนึ่งตัว
cat backend/docs/adr/001-ssh-tunnel-db-connection.md
# ต้องมี: ## Context, ## Decision, ## Consequences
2. Developer Setup Guide
คู่มือ step-by-step ให้ developer ใหม่ setup local environment และรัน project ได้ภายใน 30 นาที
P2Pass

คืออะไร

Developer Setup Guide คือ document ที่บอก developer ใหม่ว่าต้องทำอะไรบ้างตั้งแต่ clone repo จนถึงรัน server ได้ รวมถึง: prerequisites, environment variables ที่ต้องตั้ง, วิธี run migrations, วิธีรัน dev server

ทำไมถึงสำคัญ

ถ้าไม่มี setup guide developer ใหม่ต้องใช้เวลาหลายวันถามคนโน้นคนนี้ เสียเวลาทั้งทีม ยิ่งถ้า developer เดิมลาออกไปแล้ว ความรู้นั้นหายไปด้วย

สถานะในโปรเจกต์ ✓

มี backend/docs/backend.html ที่ cover การ setup project รวมถึง SSH config, environment variables (.env.example), วิธีรัน migrations และ dev server ครบถ้วน

วิธีทดสอบ / ตรวจสอบ

# เปิด docs ใน browser
open backend/docs/backend.html

# ตรวจ .env.example ว่ามี field ครบ
cat backend/.env.example | grep "^[A-Z]" | wc -l
# คาดหวัง: มี env vars ที่จำเป็นครบ

# ทดสอบ follow setup guide จริง: clone → install → migrate → run
cd backend && pip install -r requirements.txt
python migrations/migrate.py
uvicorn app.main:app --reload
3. Runbook / Operations Guide
คู่มือสำหรับ ops team: วิธี restart service, วิธี check logs, วิธีจัดการ incident
P3Pass

คืออะไร

Runbook คือ document สำหรับ operations team (ไม่ใช่ developer) บอกวิธีจัดการ task routine และ incident เช่น: "วิธี restart API server", "วิธีดู error logs", "ถ้า Redis down ทำอะไร", "ถ้า DB connection pool exhausted ทำอะไร"

สถานะในโปรเจกต์ ✓

มี backend/docs/runbook.html ครอบคลุม 6 scenarios:

  • Restart service — Docker Compose และ uvicorn โดยตรง
  • Check logs — JSON log fields, คำสั่ง filter error, Docker logs
  • Redis down — symptoms, restart steps, escalation path
  • DB / SSH tunnel error — ขั้นตอน triage SSH connection จนถึงตรวจ DB
  • High error rate — triage 5xx errors, ตรวจ Prometheus metrics
  • Rollback — app rollback ด้วย Docker image + DB migration rollback

วิธีทดสอบ / ตรวจสอบ

# เปิด runbook ใน browser
open backend/docs/runbook.html

# ทดสอบ health check command จาก runbook
curl http://localhost:8000/health
# คาดหวัง: {"status":"ok"}

curl http://localhost:8000/ready
# คาดหวัง: {"status":"ok"} ถ้า DB + Redis พร้อม
# หรือ: {"failing":["redis"]} ถ้า Redis down

# ทดสอบ restart scenario
docker compose restart api
curl http://localhost:8000/health  # ต้อง 200 ภายใน 15 วินาที

# ทดสอบ log filtering
grep '"level":"ERROR"' backend/logs/app.log | tail -5
4. Data Dictionary
อธิบาย schema ของทุก table, field name, data type และ business meaning
P3Pass

คืออะไร

Data Dictionary คือ document ที่อธิบายทุก table และ field ใน database ว่า: ชื่อคืออะไร, data type อะไร, และสำคัญที่สุด ความหมายทาง business คืออะไร เช่น gl_id ย่อมาจากอะไร, cost_ctr_id แตกต่างจาก cost_owner อย่างไร

สถานะในโปรเจกต์ ✓

มี backend/docs/data-dictionary.html ครอบคลุมทุก table ใน database:

  • erp_transactions — 22 columns พร้อม business meaning, indexes, ETL strategy
  • master_cost_ctr, master_fund, master_gl — reference tables สำหรับ cost center, fund, GL account
  • master_io_goods/activities/project/work — Internal Order master tables
  • master_ic_strategy, master_mu_strategy — ยุทธศาสตร์ IC/MU
  • finance_coordinator — system table พร้อมอธิบาย locking strategy และ cache key
  • audit_log — append-only audit trail พร้อม production security note

วิธีทดสอบ / ตรวจสอบ

# เปิด data dictionary ใน browser
open backend/docs/data-dictionary.html

# ตรวจ cross-reference: ชื่อ column ในเอกสารตรงกับ database จริง
psql -d ic_finance -c "\d erp_transactions"
# เปรียบเทียบ column names กับที่ระบุใน data-dictionary.html

# ตรวจ GL account format
psql -d ic_finance -c "SELECT DISTINCT gl_id FROM erp_transactions LIMIT 5;"
# ตรงกับที่อธิบายใน data dictionary ว่า "เช่น 51000001"

# ตรวจ fiscal_year range
psql -d ic_finance -c "SELECT DISTINCT fiscal_year FROM erp_transactions ORDER BY 1;"
# ต้องเป็น integer ปีพุทธศักราช เช่น 2566, 2567, 2568
