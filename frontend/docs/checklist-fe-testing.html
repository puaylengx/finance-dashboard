Testing — 4 requirements   Pass 3 / Partial 0 / Defer 1 / Fail 0

การทดสอบ frontend ครอบคลุม unit, component, E2E, และ visual regression

1. Unit Tests (Vitest)
ทดสอบ utility function และ composable ด้วย Vitest โดยเฉพาะ financial calculation
P2Pass

คืออะไร

Unit test คือการทดสอบ function หรือ composable แยกส่วน ไม่ต้องการ browser หรือ server ทำให้รันเร็วมาก Vitest คือ test runner ที่ใช้ Vite config เดียวกันกับ project ทำให้ setup ง่ายและ fast iteration

ทำไมถึงสำคัญ

Financial calculation เช่น การคำนวณ % งบที่ใช้ไป, การ format ตัวเลขเงิน, การ aggregate ตาม department — ถ้า bug เกิดในนี้จะกระทบตัวเลขทุกหน้า unit test จับปัญหาก่อนถึง user

สถานะในโปรเจกต์ ✓

src/
└── utils/
    ├── formatCurrency.test.ts    # formatCurrency(1234567) → "1,234,567"
    ├── calcBudgetUtil.test.ts    # remaining, usedPercent calculation
    └── dateRange.test.ts         # fiscal year boundary conditions

src/composables/
└── useFilter.test.ts             # filter state logic
# รัน unit tests
npm run test:unit
# หรือ watch mode
npx vitest --watch

วิธีทดสอบ

npm run test:unit
# ผลที่คาดหวัง: ทุก test pass, coverage report แสดงใน terminal

# ดู coverage รายละเอียด
npx vitest --coverage
# เปิด coverage/index.html ใน browser
2. E2E Tests (Playwright)
จำลอง user journey สำคัญ: login → filter → export ก่อน deploy ทุกครั้ง
P2Pass

คืออะไร

E2E (End-to-End) test คือการจำลอง user journey ทั้งหมดบน browser จริง ตั้งแต่เปิดหน้า login จนถึง export report Playwright รัน browser (Chromium, Firefox, WebKit) แบบ headless และ control ได้จาก code

ทำไมถึงสำคัญ

Unit test และ component test ทดสอบชิ้นส่วน แต่ไม่รู้ว่า flow ทั้งหมดทำงานได้หรือไม่ E2E test จับ regression ที่ unit test มองไม่เห็น เช่น API response format เปลี่ยน หรือ route guard ทำงานผิด

สถานะในโปรเจกต์ ✓

tests/
├── auth.spec.ts          # login → dashboard redirect
├── dashboard.spec.ts     # load widgets, filter by year
├── budget.spec.ts        # view budget table, drill down
└── export.spec.ts        # export PDF/Excel flow
# รัน E2E tests (ต้องรัน dev server ก่อน)
npm run dev &
npx playwright test

# รัน specific test
npx playwright test tests/auth.spec.ts

# รัน แบบมี UI (debug mode)
npx playwright test --ui

Critical paths ที่ต้องผ่านก่อน deploy

  • Auth flow: login → redirect dashboard → logout → redirect login
  • Filter flow: เลือกปี → กด filter → table data เปลี่ยน
  • Permission flow: role ที่ไม่มีสิทธิ์ → 403 page (เมื่อ Route Guard เพิ่มแล้ว)
  • Export flow: กด export → download file → ชื่อไฟล์ถูกต้อง
3. Component Tests
ทดสอบ component render และ interaction ด้วย Vue Test Utils
P3Pass

คืออะไร

Component test คือการทดสอบ Vue component แบบ isolated — mount component ใน JSDOM environment แล้วทดสอบ render output และ user interaction โดยใช้ Vue Test Utils + Vitest ร่วมกัน เป็น layer กลางระหว่าง unit test และ E2E

ทำไมถึงสำคัญ

Unit test ไม่ทดสอบ template; E2E ช้าและต้องการ browser จริง component test ตรวจสอบว่า component render ถูกต้องตาม props, emit event ถูกต้อง, และ slot ทำงานตามที่ออกแบบ — รันเร็วกว่า E2E มาก

สถานะในโปรเจกต์ — Pass

Implemented 4 component test files รวม 23 tests ผ่านทั้งหมด (npm run test:run):

  • EmptyState.test.ts (7 tests) — ทดสอบทุก variant (no-data/no-results/no-permission), custom title/description override, action slot render/hide
  • KpiCard.test.ts (7 tests) — label render, prefix/suffix, default & custom color class, sub text render/hide
  • SkeletonCard.test.ts (3 tests) — default height 80px, custom height prop, animate-skeleton class
  • StatCard.test.ts (6 tests) — label/value/unit text, subValue render/hide, indigo default colorMap, emerald colorMap, icon slot

Vitest config เพิ่มใน vite.config.ts:

/// <reference types="vitest/config" />
// ใน return object ของ defineConfig:
test: {
  environment: 'jsdom',
  include: ['src/**/*.test.ts', 'src/**/*.spec.ts'],
}

Scripts ใน package.json:

"test": "vitest",       // watch mode (dev)
"test:run": "vitest run" // CI mode (single run)

วิธีทดสอบ

  1. รัน tests ทั้งหมด (CI mode): 
    cd frontend
npm run test:run
# ผลที่คาดหวัง: Test Files 4 passed (4) | Tests 23 passed (23)
  2. รัน watch mode (dev): 
    npm run test
# vitest จะ re-run tests ทุกครั้งที่ไฟล์เปลี่ยน
  3. รัน test ไฟล์เดียว: 
    npm run test:run -- EmptyState
npm run test:run -- src/components/ui/KpiCard.test.ts
  4. ตรวจสอบ coverage (optional): 
    npm run test:run -- --coverage
# ต้องติดตั้ง @vitest/coverage-v8 ก่อน: npm install -D @vitest/coverage-v8
4. Visual Regression Test
ใช้ Percy หรือ Chromatic จับ screenshot diff เมื่อหน้าตา UI เปลี่ยนโดยไม่ตั้งใจ
P4Defer

คืออะไร

Visual regression test คือการ capture screenshot ของ component หรือหน้าเว็บ แล้ว compare กับ baseline screenshot — ถ้า pixel diff เกิน threshold ให้ fail CI โดยอัตโนมัติ ใช้ Percy (Browserstack) หรือ Chromatic (Storybook) เป็น service

ทำไมถึงสำคัญ

การเปลี่ยน CSS ที่ดูเล็กน้อย อาจทำให้ตัวเลขใน chart อ่านไม่ออก หรือปุ่มถูก overlay จนกดไม่ได้ visual regression จับปัญหาเหล่านี้โดยอัตโนมัติก่อน reach production

สถานะในโปรเจกต์ — Defer

เลื่อนออกไปก่อน เนื่องจากต้องการ external service (Percy หรือ Chromatic) ซึ่งมีค่าใช้จ่ายรายเดือน และต้องตั้ง Storybook ก่อนถ้าใช้ Chromatic

ทำหลังจาก: Component Tests (P3) เสร็จ + ตัดสินใจ service ที่จะใช้ + งบประมาณ approved

แนวทางเมื่อพร้อม

Option A: Playwright visual comparison (ฟรี, built-in)

# ไม่ต้องใช้ external service — Playwright มี snapshot built-in
await expect(page).toHaveScreenshot('dashboard.png', { threshold: 0.02 })

# รัน update baseline เมื่อ UI เปลี่ยนตั้งใจ
npx playwright test --update-snapshots

Option B: Percy (ต้องการ account)

npm install -D @percy/playwright
# ใช้ percySnapshot(page, 'Dashboard') แทน toHaveScreenshot
