Architecture — 5 requirements   Pass 3 / Partial 0 / Defer 0 / Fail 2

โครงสร้าง codebase, state management, type safety, และ security ระดับ routing

1. Component-Based Architecture
แยก UI เป็น atomic components: atom → molecule → organism → page
P2Pass

คืออะไร

Atomic Design คือ methodology แบ่ง UI ออกเป็น 4 ระดับ: Atom (Button, Input, Badge), Molecule (SearchBar = Input + Button), Organism (DataTable = ตาราง + Pagination + Filter), Page (ประกอบ organisms เป็นหน้าจริง)

ทำไมถึงสำคัญ

Component hierarchy ชัดเจนทำให้นักพัฒนารู้ว่าจะหา component ที่ไหน ลด code duplication และง่ายต่อการ test แต่ละ layer แยกกัน

สถานะในโปรเจกต์ ✓

src/components/
├── atoms/       Button, Badge, Input, Spinner, EmptyState*
├── molecules/   FilterBar, StatCard, DateRangePicker
├── organisms/   DataTable, DashboardHeader, Sidebar
└── templates/   DefaultLayout, AuthLayout

* EmptyState อยู่ในแผน (ดู UX/UI checklist)

วิธีทดสอบ

ตรวจสอบว่า atom ไม่ import organism และ molecule ไม่ import page component:

grep -rn "import.*organisms" src/components/atoms/    # ต้องไม่พบ
grep -rn "import.*pages"    src/components/molecules/  # ต้องไม่พบ
2. Pinia State Management
จัดการ global state ด้วย Pinia แยก store ตาม domain เช่น auth, budget, filter
P2Pass

คืออะไร

Pinia คือ official state management library สำหรับ Vue 3 แทน Vuex ใช้ Composition API style, TypeScript-first, และ Devtools support ที่ดีกว่า แยก store ตาม domain ทำให้แต่ละ concern อยู่ใน store ของตัวเอง

ทำไมถึงสำคัญ

Global state ที่ไม่ structured ทำให้ bug ยากหา — ไม่รู้ว่า state เปลี่ยนจากที่ไหน Pinia แก้ด้วย centralized store + devtools ที่ track ทุก mutation

สถานะในโปรเจกต์ ✓

src/stores/
├── auth.ts      # user, role, token expiry, logout action
├── budget.ts    # selected year, department, budget data
├── filter.ts    # active filters, sort order, pagination
└── ui.ts        # sidebar open/close, modal state

ใช้ defineStore + Composition API style ทุก store typed ด้วย TypeScript

วิธีทดสอบ

เปิด Vue DevTools → Pinia tab — ดู state ของแต่ละ store แบบ real-time และ time-travel debugging

3. TypeScript (Strict Mode)
ใช้ TypeScript strict mode ทั้งโปรเจกต์ กำหนด type สำหรับ API response ทุก endpoint
P2Pass

คืออะไร

TypeScript strict mode เปิดใช้ strictNullChecks, noImplicitAny, strictFunctionTypes และอื่นๆ ทำให้ type system ตรวจสอบเข้มงวดขึ้น ลด runtime error จาก undefined access หรือ type mismatch

ทำไมถึงสำคัญ

Financial calculation ที่ operate บน number | undefined โดยไม่ check จะ produce NaN โดยไม่มี error ใดๆ strict mode จับปัญหานี้ตั้งแต่ compile time

สถานะในโปรเจกต์ ✓

// tsconfig.json
{
  "compilerOptions": {
    "strict": true,       // เปิด strict mode ทั้งชุด
    "noUncheckedIndexedAccess": true
  }
}

// src/types/api.ts — typed API responses
export interface BudgetSummaryResponse {
  success: boolean
  data: {
    year: number
    total_budget: number
    used_amount: number
    remaining: number
    departments: DepartmentBudget[]
  }
}

วิธีทดสอบ

npm run type-check
# หรือ
npx tsc --noEmit
# ต้องผ่านโดยไม่มี error
4. Route Guard
ตรวจสิทธิ์ก่อน render ทุก route ด้วย Vue Router navigation guard redirect ไปหน้า login หากไม่มีสิทธิ์
P1Fail

คืออะไร

Navigation guard คือ hook ที่ Vue Router เรียกก่อน render page ใช้ตรวจสอบว่า user มีสิทธิ์เข้า route นั้นหรือไม่ ถ้าไม่มีสิทธิ์ให้ redirect ไปหน้า login หรือหน้า 403 แทน

ทำไมถึงสำคัญ

ถ้าไม่มี route guard user ที่ไม่ได้ login สามารถพิมพ์ URL ตรงๆ แล้วเข้าหน้า financial data ได้ browser render component ก่อน API call fail — ข้อมูลที่โหลดมาแล้วอาจ show ก่อน 401 redirect

สถานะในโปรเจกต์ — ยังไม่มี

ปัจจุบัน router ไม่มี beforeEach guard — ทุก route เข้าได้โดยไม่ตรวจ auth

สิ่งที่ต้องทำ

1. เพิ่ม meta ใน route definitions

// router/index.ts
const routes = [
  {
    path: '/login',
    component: () => import('@/pages/LoginPage.vue'),
    meta: { requiresAuth: false }
  },
  {
    path: '/dashboard',
    component: () => import('@/pages/DashboardPage.vue'),
    meta: { requiresAuth: true, roles: ['fa', 'coordinator'] }
  },
  {
    path: '/admin',
    component: () => import('@/pages/AdminPage.vue'),
    meta: { requiresAuth: true, roles: ['fa'] }
  }
]

2. เพิ่ม beforeEach guard

// router/guards.ts
import { useAuthStore } from '@/stores/auth'

router.beforeEach(async (to) => {
  const auth = useAuthStore()

  if (!to.meta.requiresAuth) return true

  if (!auth.isAuthenticated) {
    return { path: '/login', query: { redirect: to.fullPath } }
  }

  const requiredRoles = to.meta.roles as string[] | undefined
  if (requiredRoles && !requiredRoles.includes(auth.role)) {
    return { path: '/403' }
  }

  return true
})

3. สร้างหน้า 401 และ 403 สำหรับ redirect ที่ชัดเจน

⚠ P1 Critical — ต้องทำก่อน production เพราะ financial data เปิด public ถ้าไม่มี guard

5. Environment Configuration
แยก config ตาม environment ด้วย .env files ไม่ hardcode URL หรือ key ใน code
P2Fail

คืออะไร

Environment configuration คือการเก็บค่าที่เปลี่ยนแปลงตาม environment (dev/staging/prod) ไว้ใน .env files แทนการ hardcode ใน source code Vite ใช้ VITE_ prefix สำหรับ env vars ที่ expose ให้ browser ได้

ทำไมถึงสำคัญ

ถ้า hardcode http://localhost:8000 ใน API calls — production build จะ call localhost ซึ่งไม่มี server ทำให้ทุก API fail นอกจากนี้ hardcoded staging URL ที่หลุดไปใน production code เป็น security risk

สถานะในโปรเจกต์ — ยังไม่มี

ยังไม่มี .env files — API base URL อาจถูก hardcode อยู่ใน Axios config หรือ store

สิ่งที่ต้องทำ

1. สร้าง .env files

# .env.development
VITE_API_BASE_URL=http://localhost:8000/api/v1
VITE_APP_TITLE=Seamless Dashboard (Dev)

# .env.production
VITE_API_BASE_URL=https://api.seamless.example.com/api/v1
VITE_APP_TITLE=Seamless Dashboard

# .env.example (commit เข้า repo — ไม่ใส่ value จริง)
VITE_API_BASE_URL=
VITE_APP_TITLE=

2. ใช้ใน Axios config

// src/api/client.ts
export const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  withCredentials: true,  // ส่ง HTTP-only cookie
})

// TypeScript: declare ใน vite-env.d.ts
interface ImportMetaEnv {
  readonly VITE_API_BASE_URL: string
  readonly VITE_APP_TITLE: string
}

3. เพิ่ม .env.* ใน .gitignore (ยกเว้น .env.example)

# .gitignore
.env
.env.development
.env.production
.env.local
# แต่ commit .env.example ได้
