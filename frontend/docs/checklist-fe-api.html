API Integration — 5 requirements   Pass 3 / Partial 0 / Defer 0 / Fail 2

การเชื่อมต่อ backend API อย่างมีประสิทธิภาพ ครอบคลุม caching, error handling, loading state, และ auth flow

1. Axios + TanStack Query
จัดการ API call ด้วย Axios interceptor + TanStack Query สำหรับ caching และ background refetch
P2Pass

คืออะไร

Axios คือ HTTP client ที่รองรับ interceptor (middleware สำหรับ request/response) TanStack Query (Vue Query) จัดการ server state: caching, background refetch, stale-while-revalidate, loading/error state โดยอัตโนมัติ

ทำไมถึงสำคัญ

TanStack Query ทำให้ component ไม่ต้องเขียน isLoading, error, data เอง และ cache ผลลัพธ์ทำให้ navigation กลับไปหน้าที่เคยโหลดแล้วไม่ต้อง fetch ใหม่ — UX ลื่นกว่ามาก

สถานะในโปรเจกต์ ✓

// src/api/budget.ts
export const useBudgetSummary = (year: Ref<number>) =>
  useQuery({
    queryKey: ['budget', 'summary', year],
    queryFn: () => apiClient.get<BudgetSummaryResponse>(`/finance/summary?year=${year.value}`),
    staleTime: 5 * 60 * 1000,  // cache 5 นาที
    retry: 2,
  })

// component
const { data, isPending, isError, refetch } = useBudgetSummary(selectedYear)

QueryClient config ตั้งใน main.ts · staleTime และ gcTime กำหนด per-query

วิธีทดสอบ

เปิด Vue DevTools → TanStack Query tab — ดู cache entries, status, และ stale time ของแต่ละ query navigate ไปหน้าอื่นแล้วกลับมา — data ต้องโหลดจาก cache ทันที ไม่มี loading flicker

2. Error UI
แสดง error message ที่เข้าใจง่าย พร้อมปุ่ม Retry สำหรับทุก error state
P2Pass

คืออะไร

Error UI คือสิ่งที่แสดงเมื่อ API call ล้มเหลว แทนที่จะแสดง raw error หรือไม่แสดงอะไรเลย ต้องมี: (1) message ที่ user เข้าใจได้, (2) ปุ่ม Retry, (3) error type ที่ต่างกัน (network error vs. server error vs. permission error)

ทำไมถึงสำคัญ

User ที่เห็น blank screen หรือ raw JSON error จะ panic และไม่รู้จะทำอะไรต่อ ปุ่ม Retry ให้ user ลองใหม่โดยไม่ต้อง refresh ทั้งหน้า

สถานะในโปรเจกต์ ✓

  • ErrorState.vue component แสดง icon + message + Retry button
  • Global toast สำหรับ error ที่ไม่ block UI (เช่น background refetch fail)
  • Error message map: 400 → "ข้อมูลไม่ถูกต้อง" · 403 → "ไม่มีสิทธิ์" · 500 → "เซิร์ฟเวอร์ขัดข้อง ลองใหม่ภายหลัง"
  • TanStack Query isError + refetch ส่งต่อให้ ErrorState component

วิธีทดสอบ

ใน Chrome DevTools → Network → ขวาคลิก request → Block request domain แล้ว reload — ต้องเห็น ErrorState component พร้อมปุ่ม Retry กด Retry ต้องเรียก API ใหม่

3. Skeleton / Spinner
แสดง Skeleton Screen ระหว่างโหลดแต่ละ widget อิสระจากกัน ไม่ block UI ทั้งหน้า
P2Pass

คืออะไร

Skeleton screen คือ placeholder ที่มีรูปร่างเหมือน content จริง แต่แสดง animation ขณะโหลด ต่างจาก spinner ที่บอกแค่ว่า "กำลังโหลด" skeleton บอก layout ล่วงหน้า ลด perceived loading time

ทำไมถึงสำคัญ

Dashboard ที่มีหลาย widget แต่ละ widget โหลดข้อมูลต่างกัน ถ้าใช้ global spinner หน้าจะ block จนทุก widget โหลดเสร็จ skeleton ทำให้ widget ที่โหลดเสร็จแล้วแสดงได้ทันที ไม่รอกัน

สถานะในโปรเจกต์ ✓

  • SkeletonCard.vue, SkeletonTable.vue, SkeletonChart.vue แต่ละ widget ใช้ skeleton ของตัวเอง
  • TanStack Query isPending → show skeleton, data → show content
  • Animation ใช้ Tailwind animate-pulse บน skeleton blocks
  • Widget แต่ละตัวโหลดอิสระ — ไม่มี global loading state ที่ block ทั้งหน้า

วิธีทดสอบ

ใน Chrome DevTools → Network → Throttle เป็น "Slow 3G" แล้ว reload — ต้องเห็น skeleton ของแต่ละ widget แยกกัน และ widget ที่โหลดเสร็จก่อนแสดงได้ทันทีโดยไม่รอตัวอื่น

4. Axios Interceptor (Auth)
แนบ JWT token อัตโนมัติทุก request, handle 401 → refresh token → retry request
P1Fail

คืออะไร

Axios interceptor คือ middleware ที่รันก่อนทุก request (request interceptor) หรือหลังทุก response (response interceptor) Auth interceptor ทำ 2 หน้าที่: (1) แนบ auth credentials ทุก request, (2) จัดการ 401 Unauthorized โดย redirect ไป login หรือ refresh token

ทำไมถึงสำคัญ

ถ้าไม่มี interceptor ทุก API call ต้องเขียน auth header เอง และ 401 จะเป็น unhandled error ที่ user เห็นเป็น blank screen session หมดอายุกลางคันโดยไม่มีการแจ้งเตือน

สถานะในโปรเจกต์ — ยังไม่มี

Axios instance ยังไม่มี interceptor — ไม่มีการจัดการ 401 และ session expiry

สิ่งที่ต้องทำ

เนื่องจากใช้ HTTP-only cookie token ไม่อ่านจาก JS โดยตรง request interceptor จึงเน้นที่การ set headers อื่นๆ ส่วน response interceptor จัดการ 401:

// src/api/client.ts
import { useAuthStore } from '@/stores/auth'
import router from '@/router'

export const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  withCredentials: true,  // ส่ง HTTP-only cookie อัตโนมัติ
})

// Request interceptor — เพิ่ม headers ที่จำเป็น
apiClient.interceptors.request.use((config) => {
  config.headers['X-Requested-With'] = 'XMLHttpRequest'
  return config
})

// Response interceptor — จัดการ 401
let isRedirecting = false
apiClient.interceptors.response.use(
  (response) => response,
  async (error: AxiosError) => {
    if (error.response?.status === 401 && !isRedirecting) {
      isRedirecting = true
      const auth = useAuthStore()
      auth.clearSession()
      await router.push({ path: '/login', query: { reason: 'session_expired' } })
      isRedirecting = false
    }
    return Promise.reject(error)
  }
)

หน้า Login ควรแสดง banner เมื่อ ?reason=session_expired เพื่อแจ้ง user ว่า session หมดอายุ

⚠ P1 Critical — ไม่มี interceptor นี้ทำให้ 401 กลายเป็น uncaught error และ user ไม่รู้ว่า session หมด

5. Optimistic Updates
Update UI ทันทีก่อน server ตอบกลับ แล้ว rollback หาก error เพื่อ UX ที่ลื่นไหล
P4Fail

คืออะไร

Optimistic update คือ pattern ที่ update UI ทันทีเมื่อ user ทำ action โดยไม่รอ server ตอบกลับ ถ้า server ตอบ success ก็ดำเนินต่อ ถ้า error ให้ rollback กลับค่าเดิมและแสดง error message

ทำไมถึงสำคัญ

บน network ที่ช้า การรอ server response ก่อน update UI ทำให้รู้สึกว่า app ช้าและไม่ responsive optimistic update ทำให้ UX ลื่นกว่าบน high-latency network โดยเฉพาะ mobile

สถานะในโปรเจกต์ — ยังไม่มี

Write operations รอ server response ก่อนแสดงผลเสมอ ยังไม่มี optimistic pattern

สิ่งที่ต้องทำ (เมื่อพร้อม)

ใช้ TanStack Query useMutation พร้อม onMutate + onError rollback:

// ตัวอย่าง: toggle coordinator active status
const { mutate } = useMutation({
  mutationFn: (id: number) => apiClient.patch(`/admin/coordinators/${id}/toggle`),

  onMutate: async (id) => {
    await queryClient.cancelQueries({ queryKey: ['coordinators'] })
    const previous = queryClient.getQueryData(['coordinators'])

    // อัปเดต cache ทันที (ก่อน server ตอบ)
    queryClient.setQueryData(['coordinators'], (old: Coordinator[]) =>
      old.map(c => c.id === id ? { ...c, active: !c.active } : c)
    )
    return { previous }
  },

  onError: (_err, _id, context) => {
    // rollback ถ้า server ตอบ error
    queryClient.setQueryData(['coordinators'], context?.previous)
    toast.error('ไม่สามารถบันทึกได้ กรุณาลองใหม่')
  },

  onSettled: () => queryClient.invalidateQueries({ queryKey: ['coordinators'] })
})

P4 Low — ทำหลังจาก P1/P2/P3 เสร็จ และเฉพาะ action ที่ user ทำบ่อยและ network อาจช้า
