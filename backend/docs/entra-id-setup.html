Redirect URI — เลือก Platform เป็น SPA

Azure Portal
  1. ใน App ที่เพิ่ง register → เลือก Authentication จาก sidebar
  2. คลิก + Add a platform
  3. เลือก Single-page application (SPA)
ต้องเลือก SPA ไม่ใช่ Web — frontend ใช้ @azure/msal-browser ซึ่งใช้ Authorization Code + PKCE ทำงานใน browser โดยตรง ถ้าเลือก Web จะเจอ CORS error
PlatformFlowใช้ได้กับ MSAL Browser
SPA Single-page application Auth Code + PKCE (ไม่ต้อง client secret) ✓ ถูกต้อง
Web Web application Auth Code + client secret (server-side) ✗ CORS error

ใส่ Redirect URI ตามสภาพแวดล้อม:

สภาพแวดล้อมRedirect URI
Developmenthttp://localhost:5173
Staginghttps://staging.your-domain.com
Productionhttps://your-domain.com
สามารถเพิ่ม URI ได้หลายตัวพร้อมกัน แนะนำใส่ทั้ง dev และ production ในครั้งเดียว

เลื่อนลงหา Implicit grant and hybrid flows → ไม่ต้องติ๊ก ทั้ง Access tokens และ ID tokens (SPA ใช้ PKCE แทน)

กด Save

3

Token Configuration — เพิ่ม jobTitle Claim

Azure Portal

Backend ใช้ jobTitle จาก Access Token เพื่อ extract role และ position ของ user

job_title ไม่ปรากฏในรายการ optional claim ของ UI — ต้องเพิ่มผ่าน Manifest (JSON) โดยตรง
  1. เลือก Manifest จาก sidebar
  2. ค้นหา key "optionalClaims" ใน JSON
  3. แก้ค่าเป็น:
"optionalClaims": {
    "idToken": [],
    "accessToken": [
        {
            "name": "job_title",
            "source": null,
            "essential": false,
            "additionalProperties": []
        }
    ],
    "saml2Token": []
},
  1. กด Save
ชื่อ claim ใน token คือ job_title (snake_case) — Backend รองรับทั้ง job_title และ jobTitle แล้วใน auth_service.py

ทำไมต้องเป็น Access token ไม่ใช่ ID token?
Backend รับ Access Token จาก MSAL แล้ว validate กับ Azure JWKS → claim ต้องอยู่ใน Access Token

ตรวจสอบ claim ใน token — หลัง login ใหม่ ให้วาง access token ที่ได้จาก MSAL ที่ jwt.ms แล้วดูว่ามี field job_title ปรากฏหรือไม่

ถ้า login อยู่แล้ว → ต้อง logout แล้ว login ใหม่ เพื่อให้ Azure ออก token ใหม่ที่มี claim ครบ

  4. ค้นหาและติ๊ก permission ต่อไปนี้:

Backend — ตั้งค่า .env

Backend

เปิดไฟล์ backend/.env แล้วใส่ค่าจาก Step 1:

# Microsoft Entra ID
AZURE_TENANT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx   # Directory (tenant) ID
AZURE_CLIENT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx   # Application (client) ID
AZURE_AUTHORITY=https://login.microsoftonline.com/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

# Optional — ถ้า jobTitle ไม่ได้อยู่ใน token ให้ fallback ดึงจาก Graph API
AZURE_CLIENT_SECRET=your-client-secret   # ต้องสร้าง client secret ใน Entra App ก่อน

# Optional — domain สำหรับ UPN coordinator lookup
ENTRA_DOMAIN=company.com   # เช่น "mahidol.ac.th" — auto-build UPN เมื่อ add coordinator

# ปิด Draft Mode เมื่อพร้อม production
DRAFT_MODE=false
APP_ENV=production
APP_ENV=production + DRAFT_MODE=true → App จะ refuse to start
backend มี guard ใน config.py ที่ block combination นี้ไว้ ถ้ายังทดสอบอยู่ให้ใช้ APP_ENV=staging

Restart backend หลังแก้ไข .env:

cd backend
uvicorn app.main:app --reload

ทดสอบว่า Backend อ่าน config ถูกต้อง:

curl http://localhost:8000/health | python3 -m json.tool
Backend validate token โดย fetch JWKS จาก:
https://login.microsoftonline.com/{AZURE_TENANT_ID}/discovery/v2.0/keys
ตรวจ audience ทั้ง {CLIENT_ID} และ api://{CLIENT_ID} รูปแบบ
ถ้าตั้ง AZURE_CLIENT_SECRET: fallback ดึง jobTitle จาก Graph API ด้วย client_credentials flow (app token cached)
6

Frontend — ติดตั้ง MSAL และเชื่อม Login

Frontend

6.1 ติดตั้ง Package

cd frontend
npm install @azure/msal-browser @azure/msal-react

6.2 ตั้งค่า Environment Variables

เพิ่มในไฟล์ frontend/.env:

VITE_API_BASE_URL=http://localhost:8000
VITE_AZURE_CLIENT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
VITE_AZURE_TENANT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

6.3 สร้าง MSAL Config

สร้างไฟล์ frontend/src/lib/msalConfig.ts:

import { Configuration, PublicClientApplication } from '@azure/msal-browser'

export const msalConfig: Configuration = {
  auth: {
    clientId: import.meta.env.VITE_AZURE_CLIENT_ID,
    authority: `https://login.microsoftonline.com/${import.meta.env.VITE_AZURE_TENANT_ID}`,
    redirectUri: window.location.origin,
  },
  cache: {
    cacheLocation: 'sessionStorage',  // ปลอดภัยกว่า localStorage
    storeAuthStateInCookie: false,
  },
}

export const msalInstance = new PublicClientApplication(msalConfig)

export const loginScopes = {
  scopes: ['openid', 'profile', 'email', 'User.Read'],
}

6.4 Wrap App ด้วย MsalProvider

แก้ไฟล์ frontend/src/main.tsx:

import { MsalProvider } from '@azure/msal-react'
import { msalInstance } from '@/lib/msalConfig'

await msalInstance.initialize()  // ต้อง initialize ก่อน render

createRoot(document.getElementById('root')!).render(
  <MsalProvider instance={msalInstance}>
    <App />
  </MsalProvider>
)

6.5 Login Function

ในหน้า Login — เพิ่ม handler สำหรับ Microsoft login:

import { useMsal } from '@azure/msal-react'
import { loginScopes } from '@/lib/msalConfig'
import { entraLogin } from '@/api/auth'

const { instance } = useMsal()

async function handleMicrosoftLogin() {
  const result = await instance.loginPopup(loginScopes)
  const session = await entraLogin(result.accessToken)
  // บันทึก session.token ใน store / localStorage
}
entraLogin() อยู่ที่ frontend/src/api/auth.ts — ส่ง POST ไปยัง /api/v1/auth/entra-login พร้อม access_token จาก MSAL แล้วรับ JWT ของระบบกลับมา

ตั้งค่า jobTitle ของ Users ใน Entra ID

Azure Portal — Users

Backend อ่าน jobTitle จาก token แล้ว parse เป็น role และ position ของระบบ

รูปแบบ jobTitle ที่ระบบรองรับ

รูปแบบ jobTitleRolePositionสิทธิ์ที่ได้
FIN,FAfa-ต้องเป็น coordinator จึงเข้าได้
FIN,BBAbba-ต้องเป็น coordinator จึงเข้าได้
FIN,FA,chieffachiefเข้าได้ (scoped ตาม dept)
FIN,BBA,headbbaheadเข้าได้ (scoped ตาม dept)
FIN,SCI,chairmanscichairmanเข้าได้ (scoped ตาม dept)
FIN,TYPE,BBA,chiefbbachiefเข้าได้ (รองรับ 4 segments)
Logic การ parse: segment สุดท้ายที่เป็น chief / chairman / head → position, segment ก่อนหน้าคือ role
ดู code ได้ที่ backend/app/core/security.py → extract_claims()

วิธีตั้งค่า jobTitle ใน Azure Portal

  1. ไปที่ Entra ID → Users
  2. คลิกชื่อ user ที่ต้องการ
  3. คลิก Edit properties (ปุ่มดินสอบนสุด)
  4. เลื่อนหา field Job title
  5. ใส่ค่าตามรูปแบบ เช่น FIN,FA,chief
  6. กด Save
ระวังตัวพิมพ์ใหญ่-เล็ก — ระบบ .lower() ทุก segment ก่อน compare ดังนั้น FIN,FA,CHIEF และ fin,fa,chief ให้ผลเหมือนกัน

Troubleshooting

!

CORS error ตอน loginPopup()

สาเหตุ: เลือก Platform เป็น Web แทน SPA

วิธีแก้: Azure Portal → App registration → Authentication → ลบ Web platform → Add platform → เลือก Single-page application

!

Backend ตอบ 503 — "MS Entra ID ยังไม่ได้ตั้งค่า"

สาเหตุ: AZURE_TENANT_ID หรือ AZURE_CLIENT_ID ใน .env ว่างอยู่

วิธีแก้: ตรวจสอบ backend/.env ให้ครบ แล้ว restart backend

grep AZURE backend/.env
!

Backend ตอบ 403 — "ไม่มีสิทธิ์เข้าถึง"

สาเหตุ: jobTitle ของ user ไม่ถูกต้อง หรือไม่ได้ set position และ user ไม่อยู่ใน finance_coordinator table

วิธีแก้:

  1. ตรวจสอบ jobTitle ของ user ใน Entra ID ตามรูปแบบ Step 7
  2. หรือ เพิ่ม username เข้า finance_coordinator table ด้วย active = TRUE
-- เพิ่ม coordinator
INSERT INTO finance_coordinator (username, display_name, active)
VALUES ('user@example.com', 'Display Name', TRUE);
!

Token ไม่มี jobTitle claim

สาเหตุ: ยังไม่ได้เพิ่ม jobTitle ใน Token configuration (Step 3)

วิธีตรวจสอบ: Decode access token ที่ได้จาก MSAL ใน jwt.ms แล้วดูว่ามี field jobTitle หรือไม่

วิธีแก้: กลับไปทำ Step 3 แล้ว logout/login ใหม่เพื่อรับ token ใหม่

!

App จะ refuse to start — "DRAFT_MODE must be false"

สาเหตุ: ตั้ง APP_ENV=production แต่ DRAFT_MODE=true พร้อมกัน

วิธีแก้: ถ้าจะใช้ production → ตั้ง DRAFT_MODE=false
ถ้ายังทดสอบอยู่ → ตั้ง APP_ENV=staging
