CI/CD — 3 requirements   Pass 1 / Partial 0 / Defer 0 / Fail 2

Automated build, deploy pipeline, และ quality gates ที่ป้องกัน performance regression ก่อนถึง production

1. Automated Build & Deploy
push to main → build → test → deploy to CDN โดยอัตโนมัติ ไม่หยุด service
P2Pass

คืออะไร

CI/CD pipeline คือ automation ที่รัน build, test, และ deploy ทุกครั้งที่ push code เข้า branch หลัก โดยไม่ต้องทำ manual deploy ลด human error และทำให้ทุก deploy มี quality gate เดียวกัน

ทำไมถึงสำคัญ

Manual deploy มีโอกาสลืมขั้นตอน เช่น ลืมรัน build ก่อน หรือ deploy file เก่า automated pipeline บังคับให้ทุกอย่างเกิดตามลำดับที่ถูกต้องเสมอ

สถานะในโปรเจกต์ ✓

# .github/workflows/frontend-ci.yml
name: Frontend CI/CD
on:
  push:
    branches: [main]
    paths: ['frontend/**']

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - run: npm run type-check
      - run: npm run test:unit
      - run: npm run build
      - name: Deploy to CDN
        run: aws s3 sync dist/ s3://seamless-frontend/ --delete

Pipeline รัน type check → unit test → build → deploy ตามลำดับ ถ้า step ใด fail ก็หยุดทันที

วิธีทดสอบ

Push commit ที่มี type error เข้า main — CI ต้อง fail ที่ step type-check และไม่ deploy ดู GitHub Actions tab เพื่อยืนยัน

2. Bundle Size Budget
กำหนด max bundle size ใน CI ถ้า exceed ให้ fail build ป้องกัน performance regression
P3Fail

คืออะไร

Bundle size budget คือ limit ที่กำหนดว่า JavaScript bundle ต้องไม่เกิน X KB ถ้าเกิน CI จะ fail ทำให้นักพัฒนารู้ทันทีว่า dependency ใหม่ที่เพิ่มเข้าไปทำให้ bundle ใหญ่เกินไป

ทำไมถึงสำคัญ

ถ้าไม่มี budget check library ขนาดใหญ่สามารถแอบเข้ามาใน bundle โดยไม่มีใครสังเกต ทำให้ LCP เพิ่มขึ้นเรื่อยๆ โดยไม่รู้สาเหตุ bundle size budget เป็น guard ที่ทำงานโดยอัตโนมัติ

สถานะในโปรเจกต์ — ยังไม่มี

ยังไม่มีการกำหนด bundle size limit — dependency ใหม่เพิ่มได้โดยไม่มีการแจ้งเตือน

สิ่งที่ต้องทำ

Option 1: Vite built-in chunk size warning

// vite.config.ts
build: {
  chunkSizeWarningLimit: 500,  // warn เมื่อ chunk > 500KB
  rollupOptions: {
    output: {
      manualChunks: {
        vendor: ['vue', 'vue-router', 'pinia'],
        charts: ['chart.js', 'vue-chartjs'],
      }
    }
  }
}

Option 2: bundlesize package (fail CI จริง)

npm install -D bundlesize

# package.json
"bundlesize": [
  { "path": "dist/assets/index-*.js", "maxSize": "200 kB" },
  { "path": "dist/assets/vendor-*.js", "maxSize": "300 kB" }
],
"scripts": {
  "bundlesize": "bundlesize"
}

# เพิ่มใน CI workflow หลัง build
- run: npm run bundlesize

Option 3: Vite Bundle Analyzer — ดู visual treemap ของ bundle

npm install -D rollup-plugin-visualizer
# หลัง build รัน: npx vite-bundle-visualizer
# เปิด stats.html เพื่อดู bundle composition
3. Lighthouse CI
วัด Core Web Vitals ทุก deploy ถ้าคะแนนต่ำกว่า threshold ให้ fail
P3Fail

คืออะไร

Lighthouse CI (LHCI) คือ automated tool ที่รัน Google Lighthouse ใน CI pipeline วัด Performance, Accessibility, Best Practices, SEO score และ Core Web Vitals ทุก deploy ถ้าคะแนนต่ำกว่า threshold ที่กำหนด CI จะ fail

ทำไมถึงสำคัญ

Core Web Vitals อาจ degrade ทีละนิดโดยไม่มีใครสังเกต LHCI จับการ degrade ระหว่าง deploy ทำให้ทีมรู้ทันทีว่า PR ใดทำให้ performance แย่ลง แทนที่จะรู้ทีหลังเมื่อ user report

สถานะในโปรเจกต์ — ยังไม่มี

ยังไม่มีการรัน Lighthouse ใน CI pipeline — performance regression จะถูกจับได้ก็ต่อเมื่อ user report หรือ manual audit

สิ่งที่ต้องทำ

1. ติดตั้ง @lhci/cli

npm install -D @lhci/cli

2. สร้าง lighthouserc.json

{
  "ci": {
    "collect": {
      "url": ["http://localhost:4173"],
      "startServerCommand": "npm run preview",
      "numberOfRuns": 3
    },
    "assert": {
      "assertions": {
        "categories:performance": ["error", { "minScore": 0.85 }],
        "categories:accessibility": ["error", { "minScore": 0.90 }],
        "first-contentful-paint": ["warn", { "maxNumericValue": 2000 }],
        "largest-contentful-paint": ["error", { "maxNumericValue": 2500 }],
        "cumulative-layout-shift": ["error", { "maxNumericValue": 0.1 }]
      }
    },
    "upload": { "target": "temporary-public-storage" }
  }
}

3. เพิ่มใน GitHub Actions

# .github/workflows/frontend-ci.yml — เพิ่ม step หลัง build
- name: Run Lighthouse CI
  run: |
    npm run build
    npx lhci autorun
  env:
    LHCI_GITHUB_APP_TOKEN: ${{ secrets.LHCI_GITHUB_APP_TOKEN }}

Lighthouse CI จะ post comment บน PR แสดงคะแนนก่อน/หลัง ช่วยให้ review ง่ายขึ้น
